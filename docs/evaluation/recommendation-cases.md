## Structural: what the score can reach, and what actually limits it

Every pair above shows `Sec 0` and `F 10`. That is not a coincidence of the
sample - it is the normal case, and it collapses the formula into far fewer
distinct outcomes than four factors suggest.

An essay has no recorded function unless it is already assigned to a prompt, so
for any new essay the function factor is a constant 10. Secondary overlap is
zero on 82% of pairs (see secondary-diagnosis.md). What remains is
`25 x [same category] + semantic + 10`:

| Situation | Reachable range | Best case band |
|---|---|---|
| Same category, function unknown | 35–70 | `reusable-slight-edits` at exactly 70 |
| Different category, function unknown | 10–45 | `new-response` — **cannot reach the floor** |
| Same category, function known and matching | 45–80 | top band with headroom |
| Different category, function known and matching | 20–55 | `reusable-significant-edits` |

Measured over 2,295 pairs: **0** score exactly 70 and **21** score exactly 45.
Of the 10 pairs whose score reaches the top band, **0** sit exactly on its
boundary (7 keep the label after ceilings). One point of a noisy factor
therefore decides the label for nearly every one of the best recommendations,
which is a fragile place for the ranking to pile up.

### What supplying an essay function would do

The onboarding work already proposes capturing which prompt an essay was
written for. This bounds the effect of that, by rescoring every pair with the
function factor at each of its three possible values.

| Essay function | ≥50 | ≥60 | ≥70 | Cross-category pairs ≥50 |
|---|---|---|---|---|
| unknown (today) | 181 (7.9%) | 43 (1.9%) | 10 (0.4%) | 93 |
| known, matches prompt | 410 (17.9%) | 165 (7.2%) | 39 (1.7%) | 276 |
| known, differs | 62 (2.7%) | 14 (0.6%) | 0 (0.0%) | 15 |

Note this script sets `essayFunction: null` throughout, modelling a newly
written essay. The live path in reuse.ts supplies a function for essays already
assigned to a prompt, so an established portfolio scores higher than this table
shows - which is exactly why capturing it at creation matters.
